# 联合值访问与类型收窄：备选方案

**状态更新（2026-11-09）：** 已决定不做类型收窄，改为提供查询联合当前类型和按允许类型显式读值两项能力；`readas` 不检查当前成员，允许成员不匹配的读取，不因成员不匹配引入未定义行为或优化假设。不提供共同字段的直接访问，透明别名展开后重复分支合并。下文保留为历史检索，其中的组合和建议不是当前规则；新的场景推演见 [联合查询与显式读取](UNION_ACCESS_EXAMPLES.md)。

检索日期：2026-11-08。对应设计议题第 14 条。本文记录备选与评估；已定特性仍以 [设计决策](../DESIGN_DECISIONS.md) 为准。用户要求保留“判断成功后按值取出”为备选，并继续扩大检索。本文不确定优先顺序；新增方向不是已接受的语言规则。

检索从 Wikipedia 的 [Flow-sensitive typing](https://en.wikipedia.org/wiki/Flow-sensitive_typing)、[Tagged union](https://en.wikipedia.org/wiki/Tagged_union) 和 [Pattern matching](https://en.wikipedia.org/wiki/Pattern_matching) 展开，本轮扩展到 [Effect system](https://en.wikipedia.org/wiki/Effect_system) 和 [Uniqueness type](https://en.wikipedia.org/wiki/Uniqueness_type)。下面的具体语言规则以所链接的官方文档、标准草案和实现者手册为依据。

## 阅读入口

上一轮过早把范围缩到“受限局部收窄”和“按值取出”。扩大检索后，需要分开看三件事：**如何选择成员、如何取得数据、什么规则使后续访问仍然有效**。它们不是一组互斥的语法选项。

第 1—7 节保留此前方案。第 8—14 节补充共同字段、分支稳定性、值语义、函数副作用、访问权限、运行时访问检查和用户责任。第 15 节区分实现技术与语言规则，最后列出组合和验证场景。只看新增方向时，可从第 8 节开始。

| 已检索的取值方式 | 收益 | 主要代价 |
|---|---|---|
| 判断成功后按值取出 | 新变量类型固定，原变量换值不影响已取出的整数 | 新语法；大值可能有复制成本 |
| 受限局部收窄 | 沿用普通 `if`，语法增加少 | 共享存储需先复制；适用范围有边界 |
| `case` / 类型分支 | 同一次求值上处理多种情况 | 新控制结构与匹配规则 |
| 失败提前退出 | 成功路径不用层层嵌套 | 要检查失败分支不能落回成功路径 |
| 值加成功标志 | 可用普通函数接口表达 | 失败时值如何初始化；调用者可能忽略标志 |
| 成员指针加有效期约束 | 避免复制，支持原地操作 | 原联合被替换时指针可能失效 |
| 显式检查式取值或无检查取值 | 责任和成本可写在操作上 | 前者有失败处理；后者由用户保证前提 |

## 1. 判断成功后按值取出

Rust 的 `if let`、Swift 的可选绑定和 Zig 的可选值绑定都支持判断后取得值。Rust 还区分复制、移动和借用；这里仅借鉴按值取得新变量的部分。[Rust 模式规则](https://doc.rust-lang.org/reference/patterns.html#identifier-patterns)、[Swift 可选绑定](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/thebasics/#Optional-Binding)、[Zig 可选值绑定](https://ziglang.org/documentation/0.15.2/#if-with-Optionals)

沿用讨论中的临时语法，不代表已定语法：

```cy
type MaybeInt = i32 | null;
MaybeInt result = getnumber();

if (result is i32 n) {
    result = getnumber();
    print n + 1;
}
```

成功分支里的 `n` 是普通 `i32` 局部变量。原变量之后变成 `null`，不影响已取得的整数。用户明确写出类型，符合 Cyly 不做声明类型推断的选择。

对此例，所需行为是判断有无整数、成功时取值；不要求额外堆分配、GC 或后续的重复类型检查。大对象按值取得可能需要复制，不能保证优化器总能消除。指针值的复制不会复制它指向的数据。

普通 `if` 的 bool 条件规则可以保留；若采用上述形式，需要把它定义为显式匹配操作，而不是赋予联合值隐式真假性。它也不要求引入完整模式匹配或穷尽检查。

## 2. 受限局部收窄，必要时先复制一份

Kotlin 对收窄的存储位置设有限制；Typed Racket 甚至会放弃对定义作用域内被赋值的变量进行 occurrence typing。成熟实现并不必然追求理解所有修改路径。[Kotlin 收窄前提](https://kotlinlang.org/docs/typecasts.html#smart-cast-prerequisites)、[Typed Racket 对赋值的限制](https://docs.racket-lang.org/ts-guide/occurrence-typing.html)

Cyly 可以考虑从很小的范围开始：仅对没有被取址的、按值保存的局部变量进行直接条件收窄；直接赋值撤销旧结论。最保守的初版还可以只接受初始化后不再赋值的局部变量。这是分析范围限制，不需要增加 `readonly` 类型。

对于可能被别处修改的来源，先复制，再判断。以下仅用整数示意：

```cy
MaybeInt snapshot = result;
if (snapshot != null) {
    i32 n = snapshot;
    result = getnumber();
    print n + 1;
}
```

这里仍然做收窄，但只分析独立局部值。编译器不需要分析 `getnumber()` 能否改动原来的 `result`，也不要求追踪所有指针。

好处是复用已有语法；与方案 1 组合时，两种写法可以提供相近的取值能力。代价是限制需要清楚，某些情况要多写局部变量。快照也改变读取时机：后续使用的是复制时的值。若对象实际采用引用语义，复制一个引用不能稳定可变字段；本方案不能未经论证扩展到这种字段。

## 3. 类型分支与字面量字段匹配

ALGOL 68 使用 conformity clause 从联合值选择并取得成员；Odin 提供类型 `switch`。这是有长期先例的控制结构，不限于函数式语言。[ALGOL 68 实现者手册 §4.7](https://www.algol68-lang.org/docs/learning-algol-68-genie.pdf)、[Odin 联合与类型分支](https://odin-lang.org/docs/overview/#unions)

可把方案 1 扩展成多分支语句。以下仅展示语义，分支不贯穿的规则也属于草案：

```cy
switch (result) {
    case i32 n: { print n + 1; }
    case null: { print "没有结果"; }
}
```

控制结构对同一次求值得到的值分派，各分支使用明确类型的局部变量。只有少数联合成员时，运行时只需要对应的数据判别和取值；不要求通用运行时反射。

Cyly 可以另行选择语句形式和不做穷尽检查，不必连带接受其他语言的完整匹配系统。对于已接受的 `{ kind: "user"; ... } | { kind: "order"; ... }`，也可研究按字面量字段选择并取出对象或所需字段。

代价是增加匹配语法和作用域规则。Cyly 的透明别名不能充当不同分支身份；结构重叠的类型也不能直接套用“每个名字对应独立标签”的假设。整数与 `null` 的示例不解决所有对象匹配细节。

## 4. 取值失败就提前退出

Rust 的 `let ... else` 在匹配成功后把绑定提供给后续代码，失败分支必须离开该路径。Swift 的可选绑定也能与 `guard` 结合。[Rust 说明](https://doc.rust-lang.org/book/ch06-03-if-let.html)、[Swift 可选绑定](https://docs.swift.org/swift-book/documentation/the-swift-programming-language/thebasics/#Optional-Binding)

这可以复用方案 1 的判断与取值机制，把“成功时进入块”换成“失败时退出，成功时继续”。收益是减少缩进；代价是一个额外语法形式，以及验证失败分支不能继续到后续使用处。

若选方案 2，也可先用普通 `if (snapshot == null) return ...;` 配合局部控制流分析表达同样的意图。无需现在同时增加 `guard`、`match` 和绑定式 `if`。

## 5. 返回值和成功标志

Go 的 `v, ok := x.(T)` 同时产生值和成功标志；失败时提供该类型的零值。Odin 的联合断言也有带成功标志的形式。[Go 规范](https://go.dev/ref/spec#Type_assertions)、[Odin 文档](https://odin-lang.org/docs/overview/#unions)

Cyly 可以借鉴普通函数返回结果对象，或写入输出参数并返回 bool。其优点是容易作为接口使用，不要求把整个算法写进匹配块。

但 Cyly 没有通用默认初始化：失败时不能随便构造任意 `T`。可让调用者提供初值、失败时保持输出不变，但这样仍可能误用旧值；若改为返回 `T | null`，又回到了如何取出联合值的问题。这种接口能否作为主要取值方式，还取决于输出参数和初始化规则。

## 6. 按引用取得成员，以及借用约束

C++ `std::get_if` 成功时返回成员指针，失败时返回空指针。这省去大值复制，但指针指向原联合的内部；原联合换成其他成员后，不能继续假定先前取得的成员仍然存在。[C++ 标准草案](https://eel.is/c++draft/variant.get)

若想静态保证有效期，可以借鉴 Rust 对借用期间冲突访问的限制。[Rust 借用规则](https://doc.rust-lang.org/book/ch04-02-references-and-borrowing.html)

这两种选择都可以和按值取出并存：小值取得副本，大值在明确约束下取得引用。但仅禁止通过原变量名赋值不够，别的指针仍可能修改同一存储。保证有效期的办法还包括限制分支变化、静态访问约束、运行时访问检查，或明确交给用户保证；后文分别展开。完整所有权系统会影响整门语言，不能当作一个附带的小功能。

## 7. 显式检查式取值与无检查取值

C++ `std::get` 会检查成员是否匹配，失败抛异常；Cyclone 的带标签联合成员读取也带检查。Odin 则提供显式关闭类型断言检查的指令。[C++ 标准草案](https://eel.is/c++draft/variant.get)、[Cyclone 带标签联合](https://cyclone.thelanguage.org/wiki/Tagged%20Unions/)、[Odin 指令](https://odin-lang.org/docs/directives/)

Cyly 可分别评估：显式请求一次检查并返回确定类型的值，或由用户保证当前成员正确并执行无检查取值。前者需规定失败行为，未必需要异常展开；后者需规定违反前提的后果。已有条件判断再配检查式取值，可能产生重复判断，不能保证总会被优化掉。

这种机制可以与收窄组合，也可以承担主要取值职责；其角色尚未决定。不能把任意显式强制转换都解释成编译器已经证明正确。

## 8. 共同字段访问：当前不提供

TypeScript 允许直接使用联合所有成员都支持的操作，包括共同属性。[官方说明](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html#working-with-union-types)

这条路径不纳入当前 Cyly 能力。共同字段访问本身不要求流敏感收窄：编译器可以检查每个分支都支持该字段，并确定读取结果的类型；各分支布局可能不同，代码生成需按布局决定是否分派。不同结构也可能让字段具有相同偏移，因此不能断言每次共同字段访问都需要运行时查询。Cyly 当前选择统一先显式读取对象成员，以减少特殊访问规则。

此前评估过的写法如下，当前 Cyly 不支持最后一行直接读取联合共同字段：

```cy
type Id =
    { kind: "user"; value: i32 }
  | { kind: "order"; value: i32 };

Id id = getid();
i32 number = id.value;
```

Cyly 仍可以通过 `typeof` 选择实际分支，再用 `readas` 读取对应对象。若两个对象只是同结构的透明别名，它们在联合归一化后已经是同一个成员，根本没有两个分支可选。

**当前边界：** `readas` 可以直接使用，不检查实际成员，允许按非当前成员类型解释存储并读取；成员不匹配本身不属于未定义行为。调用者可以先查询来选择处理路径。联合对象字段访问统一放在明确读取之后。

## 9. 限制分支变化，而非禁止全部修改

这里区分三个动作：修改当前成员的数据、把联合整体替换成另一成员、取得内部成员的地址。

Nim 的传统 object variant 禁止单独修改判别字段而切换分支，也不允许取得判别字段的地址；切换分支通过整体替换完成。它并没有因此解决整体替换后的旧引用问题。[Nim 手册](https://nim-lang.org/docs/manual.html#object-variants)

Ada 则把成员取址与判别值是否固定联系起来：依赖判别值的子部件，只有在对象已知受约束时，才能按相关规则取得访问值。[Ada 2022 §3.10.2(26)](https://www.adaic.org/resources/add_content/standards/22rm/html/RM-3-10-2.html) Ada 的约束也可能在赋值时通过运行时检查执行，不能把这套设计概括成全静态、零检查。[AdaCore 记录教程](https://learn.adacore.com/courses/advanced-ada/parts/data_types/records.html)

对 Cyly 有两个不同层次的启发：

- **完整替换规则：** 可以改当前分支的数据；换分支必须一次提供完整的新值，避免标签与数据暂时不匹配。整体替换仍会使旧的收窄或内部指针失效。
- **稳定分支规则：** 对某类可被引用的对象，限制其存活期间换分支。这样可以修改当前分支的数据，同时保住该分支成员的存在性。变量改为指向另一个对象，与在原地址改造对象，是两回事。

**好处：** 把约束集中在会破坏判断的动作上，不必让所有字段都不可变；有机会与按引用取值组合。

**代价：** 会限制状态机、原地复用内存等写法。只保护 `kind` 字段不够，还要处理整体覆盖。Cyly 的字面量字段目前是普通结构字段，若把某些字段提升为特殊判别字段，需要额外规则；不能无声加入。对象不再换分支也不代表它不会被释放，内存有效期仍须处理。

## 10. 先区分普通值与显式引用

Whiley 的设计资料同时展示了结构联合、记录的值语义与显式引用类型；它说明结构化联合不必绑定到 JavaScript 式的对象共享方式。[作者的语言速查表，2014](https://whiley.org/pdfs/WhileyCheatSheet.pdf)

对 Cyly，需要明确 `Object b = a;` 的含义：是独立的对象值，还是两个名字共享同一对象？这会直接改变局部收窄的难度。若是独立值，修改 `a` 不会改变 `b` 的直接字段；若字段本身是指针，复制指针依然不会复制所指对象。

**好处：** 普通局部值可以采用简单分析，把共享修改的问题留在显式指针处。与按值取出、共同字段访问、受限收窄都能组合。

**代价：** 大值复制、移动、取址及对象内部指针的语义必须明确。值语义不等于每次必然复制全部字节，但消除复制需要条件。

Hylo 提供一个研究对照：其 `let` 参数具有独立值的保证，却可在编译器保证调用期间不受其他路径修改时通过引用传递。其 `inout` 又要求独占访问。[Hylo 参数约定](https://hylo-lang.org/docs/user/language-tour/functions-and-methods/) 这证明“无复制”可由访问约束换来；它没有证明这种约束易于实现，也不意味着 Cyly 应采用整套 Hylo。

## 11. 让函数声明它能修改什么

Flow 的官方 FAQ 展示了保守做法：对可变对象字段的判断，可能因中间一次函数调用而失效；先存入独立局部变量可以保留已读出的值。[Flow FAQ](https://flow.org/en/docs/faq/)

另一条路是给函数增加编译器检查的副作用约定。Flix 把函数可能产生的副作用放进类型与效果系统；纯函数仍可在内部使用局部可变数据。[Flix 官方说明](https://doc.flix.dev/effect-system.html)

对 Cyly，可以研究一个小得多的约定，例如“不会修改调用前已存在、外部可见的内存”。有这种保证的调用，就不会仅因共享修改而推翻先前判断；这只是候选语义，尚无关键词或语法。

**好处：** 跨函数保留判断，不要求每个调用点分析函数实现；约定主要在编译期检查，能服务多文件编译。

**代价：** 约定需要进入函数指针、库接口和递归调用的检查。通过指针修改参数也必须覆盖，外部代码声明还存在信任边界。若只允许修改特定参数，则仍要面对两个参数指向同一对象的问题。

不能只抄一个 `pure` 关键词。D 的弱纯函数允许通过参数修改数据；强纯才排除这种外部修改。[D 规范](https://dlang.org/spec/function.html#pure-functions) “不访问可变全局变量”与“不会使这个判断失效”不是同一个承诺。采用副作用约定也不要求引入代数效果处理器等控制流设施。

## 12. 用访问权限排除其他修改路径

Pony 区分“我只能读”和“所有路径都不能改”：`box` 可以只是当前引用只读，`val` 才提供全局不可变的保证。[Pony 权限说明](https://tutorial.ponylang.io/reference-capabilities/capability-subtyping)、[别名关系](https://tutorial.ponylang.io/reference-capabilities/combining-capabilities)

对 Cyly，可研究局部独占访问、稳定判别字段、真正不可变数据等不同粒度。仅禁止当前名字赋值，或传入一个只读指针，不能排除另一指针修改同一数据。

**好处：** 静态排除冲突时，可以直接访问原数据，避免复制和动态访问检查。

**代价：** 权限会影响赋值、传参、返回、结构字段和指针转换。局部范围限制可以缩小问题，但不能自动解决进入该范围之前已经存在的别名。完整能力系统远超收窄本身；其中不可变类型还会重开 Cyly 已决定暂不做 `readonly` 的议题。本节只是研究对照，不撤销该决策。

## 13. 显式选择运行时访问检查

Rust 的 `RefCell` 在借出引用时检查冲突，并用守卫记录这段访问尚未结束；共享借用期间不能经其安全接口替换内部值。[Rust 文档](https://doc.rust-lang.org/stable/std/cell/struct.RefCell.html) Swift 的独占访问规则则同时使用静态诊断和运行时检查。[Swift 实现者说明](https://www.swift.org/blog/swift-5-exclusivity/)

对联合取值，可以设想：先判断当前分支，再建立一段受保护的访问；期间重复使用成员不必反复检查分支，但其他访问必须经过同一套冲突规则。

**好处：** 不必在编译期推断所有别名，且不需要复制整个成员。这种检查不等于 GC，也不要求对象必须在堆上。

**代价：** 存在状态记录、进入检查、退出清理及冲突处理的运行时成本。裸指针若可绕开协议，保证就不成立。它可以被设计为显式选用的设施，但不是“没有运行时成本”的方案；也不能因看起来只是一个标志位就断言便宜。

## 14. 明确把某些有效性条件交给用户

TypeScript 实现者在控制流分析设计讨论中直接比较了乐观与保守处理：函数调用后继续相信旧判断，能减少拒绝合法程序，也可能保留已失效的判断。这是取舍，不是编译器已解决全部间接修改。[实现者讨论，2016](https://github.com/microsoft/TypeScript/issues/9998)

Cyly 可以独立评估一种更显式的责任边界：编译器检查局部、可直接证明的部分；对原地成员访问，由用户保证访问期间不通过其他路径换分支或使存储失效。可以配合明确的无检查操作，也可以成为某类指针的契约。

**好处：** 编译器和运行时都可保持较轻，允许底层代码直接操作内存。

**代价：** 必须说明违反契约的后果，不能继续声称所有错误都会静态拒绝。若采用未定义行为，后果也不能理解为仅仅“偶尔读错一个值”。自动乐观收窄与用户显式选择无检查访问，是不同的接口设计，应分别评估。

## 15. SSA 等技术可以帮助实现，但不替代上述语义

《Refinement Types for TypeScript》使用 SSA 表达局部变量在不同赋值点的版本，同时另行约束可变性。[作者论文，PLDI 2016](https://ranjitjhala.github.io/static/refinement_types_for_typescript.pdf)

对 Cyly 的启发是：直接赋值可以让旧版本的判断自然停止适用于新版本。这是编译器内部办法，不需要用户学习另一套声明语法，也不等于恢复声明类型推断。

但 SSA 不会自动告诉编译器未知指针写入了谁，更不能因为目标是 LLVM IR 就默认间接修改问题已经解决。前端是否接受程序，仍需可解释的语言规则；不能取决于某次后端优化恰好证明了多少。

## 可组合的方向，不是推荐排序

| 使用场景 | 可以组合的机制 | 仍需承担的代价 |
|---|---|---|
| 小的普通局部联合值 | 局部收窄、按值取出、普通 `if` 或多分支 | 赋值后的事实更新、分支合流 |
| 从共享对象读少量字段 | 判断后复制所需字段、共同字段直接读取 | 读取时机明确；指针字段仍共享目标 |
| 大成员原地修改 | 按引用取值，加稳定分支或独占访问规则 | 取址、整体替换和内存有效期约束 |
| 判断后需要调用其他函数 | 保守撤销相关事实，或依靠副作用约定保留 | 更多重新判断，或更复杂的接口规则 |
| 无法静态约束的共享存储 | 显式动态访问检查，或显式用户契约 | 运行时成本，或用户承担有效性责任 |

C++ 的 `visit` 还可把分支处理组织为可调用对象。[C++ 标准草案](https://eel.is/c++draft/variant.visit) Cyly 可用模块函数研究类似接口；没有匿名函数和泛型会影响便利程度。这改变分支代码的组织方式，并不自行解决数据如何取得或修改的问题。

后续比较应使用同一组代码，避免只凭 `i32 | null` 的短例判断：

1. 局部整数联合，判断后重新赋值。
2. 带标签的对象，只读取所有分支共有的字段。
3. 当前分支内调用其他函数，函数可能经别的指针修改原对象。
4. 大对象需要原地修改，不能接受整份复制。
5. 取得内部成员引用后，原联合整体被替换。
6. 把联合传入另一个文件的函数，或经函数指针调用。

这些情形中的别名冲突在单线程里也会发生；本轮没有承诺并发原子快照或线程安全。当前保留的是设计方向，未确定新的语言规则或最终语法。

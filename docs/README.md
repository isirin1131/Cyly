# 规范文档维护

[language-spec.typ](language-spec.typ) 是 Cyly 语言规则的权威记录，[生成的 PDF](../output/pdf/cyly-language-spec.pdf) 与源文件同步维护。本页记录文档构建、实现进度和编辑事项，不定义语言规则。

## 构建

在仓库根目录运行：

```sh
make docs
```

也可直接调用 Typst：

```sh
mkdir -p output/pdf
typst compile docs/language-spec.typ output/pdf/cyly-language-spec.pdf
```

构建使用 Typst 0.15 或更新版本，不依赖外部 Typst 包或网络。默认正文使用 Libertinus Serif 与宋体，标题使用 Avenir Next 与苹方，代码使用 Menlo。其他平台可安装 Noto CJK 字体，并通过 `--input` 设置 `cjk-serif`、`cjk-sans`、`latin-sans` 和 `mono`；使用 Make 时由 `TYPST_FLAGS` 传入参数。

修改规范后运行 `make docs`，核对源文档、PDF 提取文本和编译结果。是否检查页面图像遵守仓库 [AGENTS.md](../AGENTS.md) 中的约定。

## 编辑事项

正文使用直接的规范表述，规则、必要的解释和示例放在对应章节。讨论过程、决策状态、待办和实现进度保留在规范之外。章节与小节附有 `<ch-*>`、`<sec-*>` 标签并通过 Typst 引用关联；修改规则或调整小节结构时，同步核对相关文法、示例、标签引用及诊断索引。

第 0 章集中定义全部文法，包括词法、EBNF 记号、产生式、优先级与分组约定。第 1 章起只介绍文法无法表达的规则：源字节的解释与解码、名字解析、类型身份与约束、求值、存储布局、运行行为及实现边界。后续章节不再介绍产生式或重复说明分隔符、声明形状等语法；代码示例用于说明语义。EBNF 与这些规则共同定义语言（如 `TypeName` 与 `ClassName` 的区分依赖名字解析），不构成脱离语义约束的独立上下文无关文法。

文法写作遵守以下约定：

- 每条产生式之前写一行 `(* 中文含义 *)`，说明名称的含义和必要的使用限制，不能让读者仅凭英文缩写猜测。`Expr`、`Decl`、`Stmt`、`Init` 等名称也须解释。
- 文法引用的名称必须有定义，包括 `StringByte`、`HT`、`EOF` 等词法条件。仅能用文字描述的条件使用 `? 中文条件 ?`；不得凭空补出尚未确定的语义。
- 第 0 章内先定义依赖，再引用；相互递归的产生式放在同一组共同定义，各名称的中文含义紧邻定义。
- 文法采用单栏排版，每条产生式与中文说明保持在同一页，组内可在产生式之间分页。非终结符名称直接链接到定义；不重复抄录递归依赖，不再使用跨页依赖侧栏。
- [grammar.typ](grammar.typ) 在 Typst 编译时直接读取 [language-spec.typ](language-spec.typ) 中的 EBNF 并生成定义链接；文法出现在第 0 章之外、缺少注释、重复定义、未定义引用、跨组前向引用或组内不构成相互递归的前向引用都会使构建失败。
- 依次连接 `,` 比选择 `|` 结合更紧；易误读的长产生式使用括号明确分组。终结符引号内按原字符匹配，不执行 Cyly 字符串转义。

## 实现范围与约定

首个前端里程碑覆盖字面量、运算表达式、变量声明和赋值、`print`、代码块、`if / else`、`while`、C 式 `for`、`break / continue` 及具名控制结构，交付词法分析、语法分析、AST 输出和词法／语法错误定位。此里程碑不包含完整类型检查、执行语义、模块链接或 LLVM 后端。用于测试的语句片段输入由前端单独约定。

完整编译器尚未实现；仓库早期前端用于词法探索，规范示例尚未经过完整 Cyly 编译器验证。库容器先按具体类型实现，后续根据实际重复情况评估复用需求。

[examples/](../examples/README.md) 按当前规范提供完整单文件程序、多文件构建输入组合及独立的预期错误示例，索引列出对应章节与使用边界；这些示例不代表现有前端已支持相应能力。

实现文档需记录以下约定，并满足规范中的相关约束：

- 目标尺寸、对齐、端序、调用约定、符号规则及 ABI 相关选项。
- 模块接口中的递归类型表示与识别方式。
- 联合标签编码、宽度及标签与存储槽的布局。
- 固定异常槽的容量和布局，以及未捕获异常的终止方式。
- 各标量类型的 `print` 文本格式和入口返回值到进程退出状态的映射。
- 语法嵌套深度的计数单位与配置参数。

诊断实现建议关联原始源码位置和违反的规则；跳转目标、重复声明等错误可同时标出相关声明。错误恢复用于继续分析，不应把失败的程序报告为编译成功。诊断格式及多错误报告次序由实现约定。
